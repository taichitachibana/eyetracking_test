# 3-backテスト分析手順書

## 1. 分析目的

本分析では、3-back課題における `no_effect` 条件と `dynamic_effect` 条件の成績を比較し、動的効果がワーキングメモリ課題の遂行成績に与える影響を検討する。

同一参加者が両条件を実施する参加者内計画を基本とする。主評価項目は識別感度を表す **d-prime (`d_prime`)** とする。

## 2. 分析前に確定する事項

データを確認する前に、次の内容を研究計画書などへ記録する。

- 主評価項目: `d_prime`
- 主検定: 両側の対応のあるt検定
- 有意水準: 5% (`alpha = 0.05`)
- 対象条件: `no_effect`、`dynamic_effect`
- 対象課題: `n_level == 3`
- 除外基準
- 副次評価項目と多重比較補正方法
- 予定参加者数と、その根拠となる検出力設計

方向仮説をデータ収集前に定めていない場合、片側検定は使用しない。

## 3. 使用するファイル

1セッションにつき、次の4ファイルが出力される。

| ファイル | 用途 |
|---|---|
| `*_summary.csv` | 条件ごとの主解析、ブロック別解析 |
| `*_trials.csv` | 試行単位解析、反応時間処理、データ品質確認 |
| `*_settings.csv` | 課題設定、実施時間、バージョンの確認 |
| `*_practice.csv` | 練習成績と参加基準の確認 |

ファイルは通常、Unityの `Application.persistentDataPath/NBack_Data` に保存される。分析対象ファイルのコピーを `analysis/data` に集め、元データは変更しない。

練習試行は本課題の成績に含めない。

## 4. データ構成の確認

### 4.1 セッションの対応付け

`participant_id` と `condition` を使い、参加者ごとに次の2条件が1セッションずつ存在することを確認する。

- `no_effect`
- `dynamic_effect`

重複セッションがある場合は、採用規則を結果を見る前に決める。単純に成績の良い方を採用してはならない。

### 4.2 設定の一致

`*_settings.csv` で、少なくとも次の値を確認する。

- `n_level == 3`
- `stimulus_duration_ms`
- `stimulus_interval_ms`
- `response_window_ms`
- `target_rate`
- `stimulus_digits`
- `block_duration_minutes`
- `application_version`
- `final == True`

実験条件以外の設定が参加者間・条件間で一致していることを確認する。

### 4.3 完遂状況

主解析では原則として、`*_summary.csv` の次の条件を満たすセッションを使用する。

```text
scope == "overall"
completed == True
aborted == False
```

中断データを除外する場合もファイル自体は残し、除外人数と `abort_reason` を報告する。

## 5. データ品質管理

### 5.1 試行数

`total_trials`、`target_count`、`nontarget_count` が計画値と一致することを確認する。3-backとして判定できない最初の3試行は、現在のプログラムでは summary 集計から除外される。

### 5.2 タイミング

`*_trials.csv` の次の列を確認する。

- `timing_error_ms`
- `premature_response_flag`
- `delayed_response_flag`
- `response_count`
- `completed`

`timing_error_ms` の分布を条件別に要約し、極端な遅延が特定条件へ偏っていないか確認する。タイミング誤差による除外閾値を設ける場合は、解析前に値と適用単位（試行またはセッション）を固定する。

### 5.3 極端な成績

極端な低成績を理由に除外する場合、基準を事前に定義する。例えば、練習通過基準を本課題後の除外基準へ自動的に流用しない。除外あり・なしで結論が変わる場合は感度分析として両方を示す。

## 6. 評価指標

### 6.1 主評価項目

`d_prime` を用いる。d-primeはヒット率と誤反応率の両方を反映し、単純な正答率より反応バイアスの影響を受けにくい。

本プログラムでは、ヒット率または誤反応率が0または1の場合にも無限値にならないよう補正済みの率から算出される。

### 6.2 副次評価項目

| 指標 | 列名 | 解釈 |
|---|---|---|
| ヒット率 | `hit_rate` | ターゲットを正しく検出した割合 |
| 誤反応率 | `false_alarm_rate` | 非ターゲットで反応した割合 |
| 正答率 | `accuracy` | 全試行中の正答割合 |
| 反応時間中央値 | `hit_median_rt_ms` | 正答ターゲットへの反応速度 |
| 反応時間平均 | `hit_mean_rt_ms` | 正答ターゲットへの平均反応速度 |
| 反応時間変動 | `hit_cv_rt` | 反応時間の相対的な不安定さ |

反応時間はヒット試行だけを対象とする。分布が歪みやすいため、記述統計では中央値を優先する。反応時間が短くなっていても誤反応率が上昇している可能性があるため、速度と正確性を併せて解釈する。

## 7. 記述統計と可視化

検定前に、条件別に次を算出する。

- 参加者数
- 平均値、標準偏差
- 中央値、四分位範囲
- 最小値、最大値
- 欠損数

推奨する図は次のとおり。

1. 参加者ごとの2条件を線で結んだ対応プロット
2. 条件別のd-prime分布
3. d-primeの条件差の分布
4. ブロック別d-primeと反応時間の推移
5. `timing_error_ms` の条件別分布

棒グラフだけでは個人差や分布が見えにくいため、個々の観測値を表示する。

## 8. 主解析

### 8.1 対応の確認

参加者ごとに、次の差を計算する。

```text
difference = d_prime(dynamic_effect) - d_prime(no_effect)
```

差が正なら `dynamic_effect` 条件の識別感度が高いことを表す。

### 8.2 仮説

```text
帰無仮説 H0: 2条件の母平均d-prime差は0である
対立仮説 H1: 2条件の母平均d-prime差は0ではない
```

### 8.3 検定方法

参加者内のd-prime差に著しい歪みや極端な外れ値がない場合、対応のあるt検定を使用する。正規性は各条件の値ではなく、**条件差の分布**について確認する。

差の分布が明らかに不適切な場合は、Wilcoxon符号付順位検定を使用する。ただし、Shapiro-Wilk検定のp値だけで機械的に検定を切り替えず、Q-Qプロットと外れ値も確認する。

### 8.4 報告する値

- 各条件の平均値と標準偏差
- 平均条件差
- 条件差の95%信頼区間
- t値、自由度、p値
- 対応のある効果量 Cohen's `dz`

Wilcoxon検定の場合は、各条件の中央値と四分位範囲、検定統計量、p値、対応データ用の効果量を報告する。

## 9. 副次解析

`hit_rate`、`false_alarm_rate`、`hit_median_rt_ms`、`hit_cv_rt` などを条件間で比較する。副次解析を複数行う場合、Holm法でp値を補正する。

副次解析は探索的解析として主解析と区別して報告する。主評価項目が有意でなくても、副次評価項目だけを使って研究仮説が支持されたと結論しない。

## 10. 順序効果とブロック効果

### 10.1 条件順序

可能であれば、参加者を次の順序へ均等に割り付ける。

```text
順序A: no_effect -> dynamic_effect
順序B: dynamic_effect -> no_effect
```

`condition_order` を使って練習効果・疲労効果を確認する。全参加者が同じ順序の場合、条件効果と順序効果を分離できないため、結果の解釈に制限が生じる。

### 10.2 ブロック別解析

`*_summary.csv` の `scope == "block"` を使用し、時間経過による成績変化を確認する。推奨モデルは次の線形混合モデルである。

```text
d_prime ~ condition * block_number + condition_order + (1 | participant_id)
```

- `condition`: 条件の平均的な効果
- `block_number`: 時間経過、練習または疲労
- `condition * block_number`: 条件によって時間変化が異なるか
- `(1 | participant_id)`: 参加者ごとの基礎成績の違い

ブロック別解析を主要な結論に用いる場合は、単純な対応検定より混合モデルを優先する。

## 11. 試行単位の追加解析

試行ごとの正誤を詳細に分析する場合は、二項ロジスティック混合モデルを使用できる。

```text
is_correct ~ condition * block_number
             + condition_order
             + is_target
             + is_one_back_lure
             + (1 | participant_id)
```

反応時間を試行単位で分析する場合は、ヒット試行に限定し、必要に応じて対数変換した線形混合モデルを用いる。

```text
log(reaction_time_ms) ~ condition * block_number
                        + condition_order
                        + (1 | participant_id)
```

同一参加者の多数の試行を独立した参加者として扱う通常のt検定は行わない。これは擬似反復となり、p値を不当に小さくする。

## 12. 感度分析

次の条件で結論が変わらないか確認する。

- 除外基準を適用した解析と全完遂者の解析
- 対応のあるt検定とWilcoxon符号付順位検定
- d-primeと、ヒット率・誤反応率を分けた解析
- 条件順序を調整しない解析と調整した解析
- 平均反応時間と中央値反応時間

感度分析は、都合のよい結果を選ぶためではなく、結論の頑健性を確認するために使用する。

## 13. 結果報告テンプレート

```text
完遂した参加者XX名のうち、事前に定めた除外基準によりXX名を除外し、
両条件のデータがそろったXX名を解析した。

平均d-primeは、no_effect条件で M = X.XX (SD = X.XX)、
dynamic_effect条件で M = X.XX (SD = X.XX) であった。
対応のあるt検定の結果、条件差は［認められた／認められなかった］、
t(df) = X.XX, p = .XXX, 平均差 = X.XX,
95% CI [X.XX, X.XX], Cohen's dz = X.XX であった。
```

「有意差がない」ことを「両条件が同等である」と解釈しない。同等性を主張するには、許容できる差を事前に定めた同等性検定が別途必要となる。
